# 판정·기술 결정 및 검증 메모

## 기술 선택

- 로컬 브라우저 JavaScript와 Node.js 내장 정적 서버·테스트 러너를 사용한다. 외부 런타임 의존성이 없다. 개발 검사는 ESLint10.13.0과 자체 AST 규칙을 사용하고 lockfile로 고정한다.
- ArchUnit은 Java 바이트코드의 의존성/구조를 검증하는 도구라 브라우저 JavaScript 프로젝트에는 적용하지 않았다. 사용자가 JavaScript 구현과 ArchUnit 미도입을 선택했다.
- CSV는 브라우저 메모리에서 처리한다. 데이터베이스, 로그인, 실시간 연동, 제어, 예측, 점수화는 없다.

## 확정 업무 기준 적용

- KST 08:00/20:00 및 기준 시각 이전 가용 필터, 최근 24시간 `(T-24h,T]`.
- 알람은 `event_id` 중복/충돌과 `alarm_instance_id` 사건 단위, HEARTBEAT 제외, HIGH→MEDIUM→LOW 및 같은 등급은 장시간순.
- LOT는 시점별 최고 revision, 공란과 0 구분, 양품>투입은 확인 필요, 과거 revision 자동 대체 금지.
- 명시 승인된 메모 12종 및 승인 예시를 그대로 분류하고 나머지는 확인 필요. 조치 완료는 미확정.
- 설비 관계 불일치와 D06 취소 LOT의 인계/보류 상태를 독립 표시.
- 제공 이력 이전 상태 및 LOT/메모 수신 시각의 실제성 한계를 화면과 요약에 고지.

- 실 CSV에서 두 기준 시점 수치가 명세의 회귀 대조값과 일치.

- 현장 담당자의 실제 5분 사용성 검증은 실시하지 않았다.

- 업무와 품질 표시순서/동일순위 가용시각 기준은 승인 상세06을 적용한다. 같은 LOT의 최고 조건을 한 번 세고 메모 편입과 독립 현장 요청을 구분한다. HIGH 연결은 동일 설비 관계만 뜻한다.
- 간결1~2분 읽기와 현장 최종5분 사용성 승인은 실제 담당자 확인 전 미검증이다. 구현자 브라우저 수행과 구분한다.

## 알려진 범위 제한

- 제공 기록은 전체 현장 이력의 완전성을 보장하지 않는다.
- LOT `updated_at`, 메모 `created_at`을 확인 가능 시각으로 보는 것은 승인된 업무상 가정이지 서버 수신 시각 보장이 아니다.
- 메모 조치 완료와 연결 관계 확인/승인은 원본에 상태 필드가 없어 자동 확정하지 않는다.
- 부분 입력에서는 읽히는 범위만 제공하고 불완전 상태를 표시한다.
- 합계 수량 KPI, 인계 완료 처리, 자유 문장 의미 추론 기능은 없다.
