# ShiftBridge MVP 실행 안내

## 요구 환경

- Node.js 22.13 이상
- Windows PowerShell 또는 터미널
- 현대 브라우저
- 앱 실행은 외부 npm 패키지 설치 및 인터넷 연결 불필요. 정적검사/전체 테스트 도구는 아래 개발 의존성 설치가 필요하다.

## 실행

프로젝트 폴더에서:

```powershell
npm start
```

브라우저에서 <http://127.0.0.1:4173>을 연다. 종료할 때는 서버 터미널에서 `Ctrl+C`를 누른다.

기본 입력은 `input_data/`의 CSV 다섯 파일이다. 파일 선택은 브라우저 안에서 로컬 파일 내용을 읽어 해당 파일만 대체하며 서버로 전송하거나 원본을 저장하지 않는다. 기본 자료를 다시 불러오려면 `기본 자료`를 선택한다.

교대 기준은 KST 08:00/20:00이며 초기값은 현재 시각 기준 가장 최근 교대다. 날짜와 시각을 선택하고 `조회하기`를 누르면 과거 결과를 확인할 수 있다.

`인수인계 요약`을 열면 간결 모드가 기본이다. 알람/생산·현장/데이터 확인을 최대5건씩 보고 `간결 요약 복사`를 누른다. `전체 상세 · 모든 항목`을 선택하면 생략 없는 원본 ID/파일 위치를 조회하고 `전체 상세 복사`로 가져갈 수 있다. 요약은 검색·설비필터와 무관한 선택 교대 전체 판정이다. 상세 원본 필드를 보려면 `목록에서 원본 확인` 후 항목의 근거 버튼을 선택한다.

## 자동 검증

새 환경에서는 lockfile 기준으로 개발 검사 도구를 먼저 설치한다.

```powershell
npm ci --ignore-scripts
npm run check:static
npm run check
```

`check:static`은 AST/계층/DOM ID/모듈 순환을 검사하고 `deliverables/STATIC_CHECK_REPORT.md/json`을 생성한다. 오류/경고가 있으면 종료코드1이다. `check`는 정적검사 통과 후 전체 테스트를 실행한다. 현재65개 테스트 통과이며 자세한 변경/예외 검증은 `HARDENING_REPORT.md`다.

```powershell
npm test
```

Node 내장 테스트 러너로 CSV 파서·업무 판정·입력 경합·오류 처리·검사기 검출·로컬 HTTP 경로를 확인한다. 소스를 수정한 뒤 실행 중인 Node 서버를 재시작하면 서버 경로 처리 변경도 반영된다. 실제 화면에서 첫5분 내 업무 파악이 가능한지는 현장 사용자 확인이 별도로 필요하다.

최신 QA 결과는 `D07_QA_REPORT.md`다. `node scripts/qa-d07.mjs`로 세 과거 교대의 통계/간결·전체 예시 파일을 `deliverables/evidence/`에 재생성한다.
