## 명세 선반영과 구현 범위

구현 전에 `spec.md` FR-036~042, 상세06 SU-001~023, D07 결정 기록, AC-040~047, 기획 조건G, AGENTS 지침, plan/tasks를 수정했다. 기존 QA의 Q1(요약 범위)은 이번 관리자 답변으로 해결됐다.

- 기본 요약은 간결 모드이며 알람/생산·현장/데이터 확인 각 최대5건, 총 최대15건이다. 각 항목의 ID·상태·사유·다음 조 확인·근거와 잔여 수를 표시한다.
- 전체 상세 모드는 모든 인계/확인 항목과 관련 메모, 원본 파일/물리 행·식별자를 조회/복사한다. 요약은 검색/설비필터와 무관한 선택 교대 전체 결과임을 안내한다.
- 업무 순서는 보류→진행→메모LOT→기타 현장 요청이며 동일 순위 최신 가용 시각이 이른 순이다. 같은 LOT의 여러 인계 사유는 한 업무로 유지한다. 실제로 LOT 편입에 사용한 메모를 독립 업무로 다시 세지 않는다.
- 미해결 HIGH와 LOT의 동일 설비 관계를 표시한다. 실제 피해나 위험 등급으로 확정하지 않는다.
- 데이터 확인은 승인된 유형 순, 같은 유형은 최신 가용 시각이 최근인 순이다. 원본에 없는 충돌 사례는 합성 테스트로 검증했다. 실제 제공 자료에는 해당 충돌이 없어 첫 품질 항목이 LOT-XBAD 수량 모순인 것이 정상이다.
- 최고 revision 충돌은 같은 사유를 버전/수량 확인 두 건으로 중복 생성하지 않도록 정리했다. 기존 실제 CSV 수치는 바뀌지 않았다.
