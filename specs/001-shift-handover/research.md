# 기술 검토와 결정

## ArchUnit 적합성

- 공식 프로젝트: https://github.com/TNG/ArchUnit
- 공식 설명/설치: https://www.archunit.org/userguide/html/000_Index.html
- 확인 결과: Java 바이트코드의 패키지/계층/순환 의존성을 검사하는 테스트 라이브러리다. CSV 업무 판정의 정확성이나 JavaScript 모듈을 직접 검사하는 도구가 아니다.
- 로컬 환경에는 JDK17과 Node24가 있고 기존 제품 소스/빌드 구성은 없었다.
- 결정: 사용자가 브라우저 JavaScript로 간결하게 구현하고 ArchUnit을 도입하지 않는 방식을 선택했다. ArchUnit을 위해 Java 백엔드를 추가하지 않는다. 동명의 다른 생태계 포트를 임의 설치하지 않는다.

## 선택 기술

- 네이티브 ES 모듈/HTML/CSS: 작은 로컬 도구에 빌드 단계와 프레임워크를 추가하지 않는다.
- Node 내장 HTTP/node:test: 이미 설치된 런타임을 재사용하고 추가 패키지 설치를 생략한다.
- CSV 파서: 따옴표·이스케이프·멀티라인·BOM·CRLF와 행 위치를 테스트하는 작은 읽기 전용 파서. 잘못된 파일/행은 부분 결과 경고로 보존한다.
- 시간: KST(+09:00)로 엄격 파싱하며 업무 엔진에 T를 전달한다. UI 기본 시각만 실제 현재 시각을 사용한다.
- 데이터 입력: 기본 input_data를 읽고 선택적 로컬 CSV 선택으로 파일별 대체 가능하게 한다. 선택한 파일은 업로드/저장하지 않는다.
- 미결 기술/업무 선택 없음. 업무 내용·긴급도·완료 여부를 추가 추론하지 않는다.
