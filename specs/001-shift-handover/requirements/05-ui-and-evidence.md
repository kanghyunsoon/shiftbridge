# 05. 화면·원본 근거·요약 명세

관련 대표 요구: FR-028~FR-035. 기획: 조건 E. 화면의 배치·스타일·기술 스택은 여기서 고정하지 않는다.

D07 갱신: 기본 간결 요약/별도 전체 상세, 5+5+5건 제한 및 새 표시 순서는 [상세06](06-summary-and-display-order.md)을 따른다. 전체 상세의 메모 분류/확인/완료/관계 정보를 보존하며 간결은 선택된 항목만 같은 정보를 요약한다.

## 사용자 흐름

1. 로컬 도구를 열어 현재 기준 가장 최근 교대를 확인하거나 과거 교대를 선택한다.
2. 우선 알람, 이어받을 업무, 상태/데이터 확인 필요를 구분해 본다.
3. 항목을 선택해 인계 사유·현재 확인 내용·해당 시점 원본을 확인한다.
4. 같은 결과의 짧은 인수인계 요약을 확인하고 텍스트로 복사한다.

## 필수 정보

| 규칙 ID | 화면/영역 | 표시해야 할 정보 |
|---|---|---|
| UI-001 | 공통 | 선택 T, KST, 제공 기록 기준, 이력 한계 |
| UI-002 | 우선 확인 알람 | 설비·코드·심각도·미해결 지속시간·사유·관련 LOT·재발 횟수/마지막 발생 |
| UI-003 | 이어받을 업무 | LOT/메모 ID, 진행/보류/메모 기반 사유, 후속 확인/지속 관찰 구분, 다음 조 확인 사항, 조치 완료 미확정 |
| UI-004 | 상태/데이터 확인 필요 | 대상 ID, 문제 유형, 해당 필드, 확인 이유, 업무 목록과의 관계 |
| UI-005 | 상세 | 원본 식별자·설비·시각·revision·수량·메모 원문·출처와 판정 연결, 승인된 분류 근거·다음 조 확인 사항·조치 완료/관계 상태 |
| UI-006 | 범위 안내 | 당시 가용 이력 시각, 이력 이전 상태 미확인, 현재 수집 완료 보장 없음 |
| UI-007 | 요약 | T·우선 알람·생산/현장 업무·데이터 확인·근거 ID·이력 한계 |

## 업무와 데이터 품질의 동시 표시

- UI-010: 불확실한 데이터 문제를 긴급 알람처럼 섞어 놓지 않는다.
- UI-011: 업무와 오류가 함께 있으면 업무 사유는 유지하고 오류 상세로 이동할 수 있게 한다.
- UI-012: 목록 중복 노출을 새 사건이나 새 LOT로 세지 않는다. 확인 사유 수와 고유 대상 수를 혼용하지 않는다.
- UI-013: 실제 피해·최고 위험 설비·정상 보장 같은 미확정 결론을 생성하지 않는다.
- UI-014: `생산 완료`와 `후속 업무 완료 미확정`을 함께 표현할 수 있어야 한다.
- UI-015: 메모 성격 4분류·분류 승인 근거·조치 완료 미확정·연결 관계 확인 필요를 서로 다른 정보로 표시한다. 참고 분류나 분류 승인 완료를 실제 업무 완료로 바꾸지 않는다.
- UI-016: 자료 입력 누락 의심은 `자료 누락 여부 확인 필요`로 표시한다. 분류 확인 필요 메모는 원문과 `후속 요청 여부 확인 필요`를 제공하고 실제 조치를 확정 지시하지 않는다.
- UI-017: D06 조건의 취소 LOT는 업무 목록에서 메모 기반 인계 확정·후속 업무 있음으로 표시하고 데이터 확인 영역에서 보류 수량 미확인·보류 관련 확인 필요성 미확정을 표시한다. 조치 완료는 미확정이며 메모만으로 긴급을 확정하지 않는다. LOT 전체에 후속 확인 여부 미확정을 붙이지 않고 같은 LOT임을 연결한다.

## 원본 근거

- EV-001: 각 항목에 판단에 사용한 당시 가용 원본을 연결한다. 단순히 CSV 전체를 열어 주는 것만으로 충족하지 않는다.
- EV-002: file/원본 위치/event_id/instance/lot_id/revision/note_id 중 해당하는 식별 정보를 제공한다.
- EV-003: 중복 제거 후에도 모든 동일 원본 출처가 추적되고 충돌 후보를 비교할 수 있어야 한다.
- EV-004: 인계 사유의 알람·LOT·메모 역할을 구분한다. 같은 설비라는 관계를 인과 증거로 바꾸지 않는다.
- EV-005: 미래 기록은 상세·관련 원본·요약에서도 해당 과거의 근거로 노출하지 않는다.

## 복사와 상태

- UI-020: 현재 T의 요약을 텍스트로 복사하고 성공/실패를 알린다. 실패를 성공으로 표시하지 않는다. 메모의 4분류·다음 조 확인 사항·조치 완료 미확정과 관계 경고를 요약에서도 보존한다. D06의 인계 확정과 보류 관련 미확인도 서로 구분해 보존한다.
- UI-021: 실제 복사가 불가한 환경에서도 요약 원문을 선택해 가져갈 수 있게 한다.
- UI-022: 기준 변경 중 이전 T 목록과 새 T 제목이 섞이지 않아야 한다.
- UI-023: 결과 없음, 가용 기록 없음, 입력 오류, 계산/복사 실패를 구분한다. 데이터 없음은 정상 확인 결과가 아니다.
- UI-024: 입력 오류 후 읽을 수 있는 부분은 제공하고 불완전 상태·오류 범위·확인 불가를 화면과 요약에 표시한다(D04 확정). 읽지 못한 부분을 정상/0건으로 표현하지 않는다.

## 수용 예

1. Given 진행 LOT에 수량 오류도 있음, When 화면을 봄, Then 진행 업무와 품질 확인이 구분되고 두 항목이 같은 LOT임을 알 수 있다.
2. Given 과거 교대를 선택함, When 상세와 복사 요약을 봄, Then 모든 근거는 선택 T까지 가용하다.
3. Given 클립보드 접근 실패, When 복사를 누름, Then 실패 안내와 가져갈 수 있는 요약 원문이 제공된다.
4. Given 데이터가 전혀 가용하지 않은 시점, When 화면을 봄, Then 공장 정상이나 실제 업무 0건 보장으로 표현하지 않는다.
