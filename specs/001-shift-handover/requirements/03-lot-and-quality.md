# 03. LOT 버전·업무 인계·수량 품질 명세

관련 대표 요구: FR-016~FR-022, FR-026~FR-027. 기획: 조건 C.

D07 표시 순서: 보류 양수→진행→유효 메모 편입 LOT이며 같은 LOT는 최고 순위로 한 번만 표시한다. 최신 가용 시각 이른 순/관련 HIGH 표시와 기타 현장 요청은 상세06의 통합 업무 규칙을 따른다. 이 순서는 실제 위험 등급이 아니다.

## 최신 상태 선택

- LT-001: T까지 가용한 스냅샷만 lot_id 단위로 비교한다. CSV 행 수는 생산 건수가 아니다.
- LT-002: revision을 숫자 버전으로 비교해 최고 버전을 선택한다. 문자열 순서나 updated_at만으로 대체하지 않는다.
- LT-003: 같은 lot_id/revision의 완전 동일 기록은 중복이며 충돌이 아니다.
- LT-004: 최고 동일 revision이 서로 다르면 선택하지 않고 후보 원본과 충돌 이유를 제공한다.
- LT-005: 최신 버전이 수량 오류여도 이전 버전을 현재 정상 상태로 자동 대체하지 않는다.
- LT-006: 수량 검증과 revision 선택은 별개다. 원본 오류 버전과 값은 그대로 조회 가능해야 한다.
- LT-007: 최고 버전이 미래에만 가용하면 당시 가용 최고 버전을 쓴다. 미래 정정 존재를 과거 인계 사유로 쓰지 않는다.

## 인계 결정표

| 규칙 ID | 조건 | 업무 목록 | 데이터 확인 |
|---|---|---|---|
| LT-010 | IN_PROGRESS | 진행 인계 | 별도 오류가 있으면 병행 |
| LT-011 | hold_qty > 0 | 보류 인계, 상태 무관 | 별도 오류가 있으면 병행 |
| LT-012 | COMPLETE, 보류 0, 후속 확인/지속 관찰 사유 없음 | 기본 LOT 인계 제외 | 별도 오류가 있으면 표시 |
| LT-013 | COMPLETE, 보류 0, 최근 24시간 후속 확인/지속 관찰, 설비 일치 | 메모 기반 후속 인계 | 완료 여부 미확정 유지 |
| LT-014 | CANCELLED, 보류 양수 | 보류 인계 | 취소 자체는 긴급 아님 |
| LT-015 | CANCELLED, 최근 24시간 후속 확인/지속 관찰, 설비 일치 | 메모 기반 후속 인계 | 보류 미확인은 독립 표시 |
| LT-016 | CANCELLED, 확정 후속 근거 부족 | 확정 후속 업무로 만들지 않음 | 후속 업무 존재 미확정. 유효 메모가 있는 LT-015에는 적용하지 않음 |
| LT-017 | CANCELLED, hold_qty 공란/NULL, 편입 조건 충족 메모 있음 | 메모 기반 인계 확정·후속 업무 있음 | 보류 수량 미확인·보류 관련 확인 필요성 미확정·조치 완료 미확정, 메모만으로 긴급 확정 금지 |
| LT-018 | IN_PROGRESS, hold_qty 공란/NULL | 진행 인계 유지 | 보류 수량 미확인 |
| LT-019 | 메모 설비와 LOT 설비 불일치 | 메모만으로 신규 편입 금지 | 연결 확인 필요, 원본 관계 유지 |

LT-013/015는 승인된 후속 확인·지속 관찰 문구를 모두 인계 사유로 사용하며 직접 LOT 참조·최근 24시간·설비 일치를 함께 요구한다. 참고 정보·분류 확인 필요는 그 메모만으로 LOT를 신규 편입하지 않는다. 자료 입력 누락 의심은 확인 업무이며 실제 누락 확정이 아니다. 이미 진행/보류 사유가 있는 LOT는 관계 불일치 때문에 인계에서 제거하지 않는다. 동일 LOT의 여러 인계 사유는 합쳐 보여줄 수 있지만 LOT 건수를 늘리지 않는다.

후속 근거가 없는 취소 LOT에만 LT-016을 적용한다. LT-015와 LT-017이 동시에 성립하면 다음 독립 상태를 사용한다(D06 관리자 최종 승인).

| 판단 축 | 표시 |
|---|---|
| LOT 상태 | CANCELLED |
| 인계 대상 여부 | 확정 |
| 후속 업무 존재 | 있음: 승인된 후속 확인/지속 관찰 메모 |
| 보류 수량 | 미확인 |
| 보류 수량 관련 후속 확인 필요성 | 미확정 |
| 조치 완료 여부 | 미확정 |
| 긴급도 | 메모 연결만으로 긴급 확정하지 않음 |
| 근거 | 당시 가용 LOT 스냅샷 + 직접 연결된 메모 원본 |

LOT 전체에 `후속 확인 여부 미확정`을 붙이지 않는다. 확정된 후속 업무와 보류 관련 미확정을 구분한다. 보류 수량 미확인은 인계 대상 여부를 취소하는 조건이 아니다. 같은 LOT가 업무 목록과 데이터 확인 목록에 나타나더라도 고유 LOT는 1개다.
보류가 이후 가용 스냅샷에서 0으로 확인되면 보류 수량 미확인 표시는 해소하되, 유효한 메모 사유가 남아 있으면 메모 기반 인계는 유지한다. 이 기준은 기존 최근 24시간·직접 참조·설비 일치 규칙을 변경하거나 완료 관리 기능을 추가하는 것이 아니다.

## 수량 조건

- LT-020: 공란·NULL은 미확인이고 숫자 0은 0이다. 두 값을 구별한다.
- LT-021: good_qty > input_qty는 수량 모순으로 데이터 확인 대상이다. LOT-XBAD를 정상 완료 데이터처럼 숨기지 않는다.
- LT-022: 양품+불량+보류와 투입량의 불일치만으로 확정 오류를 만들지 않는다.
- LT-023: 원본 수량을 보정·잔량으로 역산하지 않는다. 검증 안 된 수량을 정상 합계에 넣지 않는다.
- LT-024: MVP는 정상 생산 수량 합계 KPI를 제공하지 않는다. 업무 대상 건수와 개별 원본 수량은 구분한다.
- LT-025: 파싱 불가 등으로 수량을 판단할 수 없으면 그 필드를 확인 불가로 남긴다. 별도 규정 없는 정상 수량 허용치를 만들지 않는다.

## 수용 예

1. Given revision 2가 T 이후 갱신됨, When T를 조회함, Then revision 1만 현재 판정의 근거다.
2. Given revision 2의 양품이 투입 초과, When 둘 다 가용함, Then 오류 버전 2를 보여주고 버전 1로 숨기지 않는다.
3. Given 진행 LOT에 hold 공란, When 목록을 조회함, Then 진행 인계와 보류 미확인이 함께 존재한다.
4. Given 완료·보류 0이고 불일치 메모만 연결됨, When 목록을 조회함, Then 메모와 관계 확인은 표시하되 메모만으로 LOT를 신규 인계하지 않는다.
