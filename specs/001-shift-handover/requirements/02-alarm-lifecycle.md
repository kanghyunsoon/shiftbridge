# 02. 알람 사건·상태·우선순위 명세

관련 대표 요구: FR-007~FR-015. 기획: 조건 B. 핵심 질문: 지금 해결되지 않은 중요한 문제는 무엇인가?

## 식별과 중복

- AL-001: event_id는 이벤트, alarm_instance_id는 발생 사건 식별자다. 서로 대체하지 않는다.
- AL-002: 가용 기록에서 같은 event_id의 모든 값이 같으면 한 번만 반영한다. 모든 원본 출처는 확인 가능해야 한다.
- AL-003: 같은 event_id의 값이 다르면 충돌이며 임의로 마지막 행·해제·최신 수신을 선택하지 않는다.
- AL-004: 같은 설비/코드의 다른 instance를 하나로 합치지 않는다.
- AL-005: RAISED/CLEARED의 instance가 없으면 다른 사건에 임의 연결하지 않는다.
- AL-006: HEARTBEAT의 instance/code 공란은 신규 알람·상태 불명 알람 1건의 근거가 아니다. HEARTBEAT 자체가 모순된 ID를 재사용하는 별도 사례는 원본 충돌로 보존한다.

## 사건 상태

| 규칙 ID | 가용 상태 전환 기록 | 결과 |
|---|---|---|
| AL-010 | 식별 가능한 RAISED만 있고 유효 후속 CLEARED 없음 | 미해결 |
| AL-011 | 같은 사건의 유효 RAISED 이후 유효 CLEARED | 해결, 긴급 목록 제외 |
| AL-012 | CLEARED만 있음 | 상태 확인 필요 |
| AL-013 | RAISED와 CLEARED의 occurred_at 동일 | 상태 확인 필요 |
| AL-014 | 해제가 발생보다 앞서거나 식별 관계가 모순됨 | 상태 확인 필요 |
| AL-015 | HEARTBEAT만 존재 | 알람 발생/해제 사건으로 만들지 않음 |
| AL-016 | 식별자 충돌·설비/코드 모순으로 상태 확정 불가 | 상태 확인 필요 |

유효 해제는 같은 사건 식별과 모순 없는 설비/코드 및 발생보다 뒤의 발생 시각을 충족해야 한다. 같은 사건에 중복 제거 후 복수 전환이 남아 다른 해석이 가능한 경우에도 임의 해결 처리하지 않는다. 이때 불확실성 사유와 모든 당시 가용 원본을 제공한다. 해제의 수신이 더 빠르더라도 두 기록이 T에 모두 가용하면 실제 occurred_at 관계를 확인한다.

## 우선순위·지속시간

- AL-020: 확정 미해결을 HIGH→MEDIUM→LOW 순서로 보여준다.
- AL-021: 같은 심각도는 지속시간이 긴 순서이며 지속시간은 T-유효 RAISED.occurred_at이다.
- AL-022: 불확실한 사건을 확정 미해결 건수·지속시간 순위에 섞지 않는다.
- AL-023: 오래된 LOW를 HIGH보다 먼저 올리거나 HIGH 발생 건수로 설비 위험도를 확정하지 않는다.
- AL-024: 연결 진행/보류 LOT는 관계 배지다. 실제 생산 피해·원인·안전 등급을 추론하지 않는다.
- AL-025: 완전히 같은 정렬 조건의 화면 순서는 위험 우열이 아닌 안정적 표시 순서로만 정한다.

## 최근 24시간 재발

- AL-030: 동일 설비/코드에서 최근 24시간의 별개 유효 발생 instance가 2개 이상이면 재발 표시한다.
- AL-031: 횟수는 이벤트 행 수가 아니라 사건 수다. 중복·HEARTBEAT·고아 해제를 넣지 않는다.
- AL-032: T까지 가용한 RAISED의 occurred_at으로 `(T-24시간,T]` 범위를 판단한다. 정확히 24시간 전은 제외한다(D05 확정).
- AL-033: 발생 횟수와 마지막 발생 시각을 보여주되 위험 등급과 기본 정렬을 변경하지 않는다.
- AL-034: 충돌한 발생의 횟수를 확정 수치에 몰래 더하지 않는다. 필요한 경우 미확정 근거로 별도 제공한다.

## 원본 상세·수용 예

사건 ID·설비·코드·심각도·발생/해제/수신 시각·불확실 사유·원본 행을 제공한다. 해결 사건도 근거 조회에서 상태를 확인할 수 있어야 한다.

1. Given 같은 사건의 동일 발생 이벤트 2행, When 교대를 조회함, Then 미해결 1건이며 원본 두 위치를 조회할 수 있다.
2. Given 같은 설비/코드에 서로 다른 두 instance, When 둘 다 기간 내 가용함, Then 별개 사건으로 유지하고 재발 횟수 2를 표시한다.
3. Given LOW 10시간과 HIGH 1분 미해결, When 목록을 조회함, Then HIGH가 먼저다.
4. Given 발생 없는 해제, When 목록을 조회함, Then 해결이나 신규 미해결 대신 상태 확인 필요다.
